桌号拦截点(关键):「开始点餐」「AI帮你选」「一席成宴」三个首页按钮都会拦桌号;但导航栏「全部菜单」直入不拦,可无桌号浏览加购。桌号真正强制在结算时(checkoutCart:无桌号→openTablePicker→选完自动续结算)。选桌器含「打包带走」选项(tableNumber='打包');扫桌码 ?t=桌号.签名 会直接锁桌并出现「本桌账单」入口。
防刷口径(2026-10-06 修正):下单频度守卫按「桌号 → 登录用户名 → IP」三级取 key,60 秒 5 单。无桌号订单不再共用 IP 桶(堂食 Wi-Fi 同 NAT 出口不互相误伤)。
售罄链路:admin 一键售罄 → 菜单灰化+角标、推荐池排除(冷启动与偏好推荐均过滤)、结算服务端最后拦截(POST /api/order 重算时校验)。
起售数量:「X个起」的菜入车按最小起售量;购物车减量与结算都有下限防线。
鉴权两档:softAuth 游客可用(下单/推荐/评价/一桌菜);authMiddleware 需登录(收藏/历史/偏好/订单状态)。一桌菜的「已点排除」仅登录用户生效(游客无身份,不继承他人记录)。
状态存储:sessionStorage 桌号·订单轮次·给别桌中间态;localStorage 用户·收藏·购物车·深色模式·菜单语言·菜品缓存(dishDataCache,弱网兜底)。
赠菜记账:被赠桌 0 元(原价划线),本桌正常计费,两边账单独立。
中英切换:导航栏 EN 按钮切换菜名/分类/描述语言,记忆在 localStorage;后台可为菜品维护英文字段。
订单状态实况:看板一键「完成」(二次确认)从 pending 直达 completed 并记 completed_at;confirmed/preparing/cancelled 仅 API 合法、暂无界面入口(取消订单需直接调 API)。
服务与部署:静态文件按服务启动目录实时读盘(改代码后页面没变=服务起的不是这份);当前 pm2 应用 tangmao 从 worktree 目录起;启动需 .env 含 TABLE_SECRET(≥16 位,worktree 与主目录密钥必须一致);改 server.js 须重启服务(pm2 restart tangmao),改前端刷新即可。
