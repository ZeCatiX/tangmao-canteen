## 2. 目标与验收总纲

**北极星目标**：单店单时段真实试用，首批 30-50 笔真实订单全流程跑通（点餐→厨房→完成→结算对账），并收集 50+ 条真实顾客反馈。

**三类角色验收标准**：

| 角色 | 验收标准（全部可验证） |
|---|---|
| 顾客 | 扫码→点餐→付款→吃饭，全程 ≤3 分钟、无需注册、无需装 App；断网/慢网下菜单仍可浏览 |
| 商家 | 老板不看文档能独立完成：改价格、标售罄、看当日单量、对账一笔订单 |
| 管理者 | 连续 7 天服务器无人工干预存活；备份恢复演练通过；有任意异常时能在 10 分钟内收到通知 |

## 8. 增补（v1.1 · 2026-09-23）：品牌真实定位与会所线、AI 一桌菜功能

### 8.1 品牌真实定位（公开信息调研实证）

唐猫庭院不只是"一家餐饮店"，是西安国潮餐饮头部品牌：

- **三店矩阵**：① 大唐不夜城店（慈恩路46号，游客打卡旗舰，点评4.7分、商圈人气榜第1，人均¥80）② 赛格国际12楼花园餐厅（商圈店，人均¥75）③ **山上私人会所（公开渠道查不到，预约订餐制，定位私密宴请）**
- **流量**：抖音 #唐猫庭院# 曝光约2亿次，官方号粉丝约546万/获赞6400万+；店员猫面具古装、"花式开酒"表演式服务出圈
- **客群**：游客打卡为主力（"在大唐不夜城只有一顿饭机会，这里是首选"）+ 本地待客宴请
- **招牌**：毛笔酥、葫芦鸡、梆梆肉、西府一口香、紫阳蒸盆子、乌龙茶香排骨

### 8.2 对项目的三个校准

1. **客群再定位**：游客打卡为主力（非本地常客）→ 扫码首屏应优先"必点榜/招牌菜"曝光（菜单"招牌与游西安必打卡"分类方向正确，需加重）
2. **扫码页 = 品牌体验延伸**：546万粉丝因猫IP而来，扫码第一屏是线上门面——唐猫视觉（插画/动画）应加重而非弱化
3. **排队等位**是网红店真实痛点，列为阶段4候选功能

### 8.4 一桌菜组合推荐 · MVP（✅ 2026-09-23 已落地）

> 草案立项当日完成 MVP。实现与草案的差异见「落地记录」。

**输入**：人数、预算（可选，默认人均80）、忌口/过敏（登录用户从档案带出）、辣度档（可选）

**输出**：三套一桌菜单（家常版/宴请版/打卡版），每套 = 凉菜×⌈N/2⌉ + 热菜×N + 招牌必点×1-2 + 主食×1-2（池子不足自动缩配额）；每道菜一句话推荐理由；总价/人均汇总；支持整体加购或单道更换

**组合算法 v1（规则引擎，非生成式）**：
1. 忌口/过敏硬过滤（allergies + is_active + 测试脏数据排除）
2. ML 单菜评分排序（现有 HistGB，worker 挂了本地规则分兜底）
3. 按 category 分池（凉菜/热菜/主食/招牌；「热菜」分类全是测试脏数据，热菜池=传承陕菜+热销菜品+江湖海鲜+田园时蔬·汤羹；主食池=主食+陕西小吃面点关键词）
4. 轮转选取：每轮 招牌→热菜→凉菜→主食 各一道，预算内贪心，辣度分散+食材不重复，预算不足缩配额不超支
5. 输出组合 + 每道菜一句话理由

**落地记录（2026-09-23）**：
- 后端：`table_recommend.js`（纯函数规则引擎，可脱离服务单测）+ `POST /api/recommend/table` / `POST /api/recommend/table/swap`（softAuth + 独立限流 TABLE_RATE_LIMIT_MAX，默认 30 次/15分）；worker 调用抽成共享 FIFO 分发 `dispatchToWorker`，predict-rf 与一桌菜共用同一条队列
